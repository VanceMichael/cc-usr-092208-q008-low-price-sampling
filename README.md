# 畸低价格产品抽检布控

依据价格、质量和历史风险组织线上线下一致的产品抽检。

## 领域资料

`contracts/domain.schema.json` 规定共享资料结构，`fixtures/domain.json` 保存不含真实个人信息的示例。当前参与方包括质量监管中心、电商平台、批发市场执法人员、检验实验室。

资料所依据的领域事实如下：

- 监管计划对价格畸低、安全风险大和历史合格率不高产品加大抽查
- 电商平台与批发市场是重点抽查领域
- 监管将提高线上线下一致性
- 电商链接不断迁移、批发市场摊位频繁更换，单一低价阈值布控容易被规避
- 单一低价阈值会让有限检验能力反复投向同一类商品
- 风险布控综合价格分布、历史抽检、投诉、认证、商家关联与渠道曝光
- 每个样品入选须结合地区、品类与实验室能力说明原因
- 主体改名、季节波动、计划撞车、样品失效或风险突然升级时可以重排资源
- 重排后原始计划仍需保留，供复盘命中率、覆盖盲区与商家规避行为

资料同时遵守以下约束，其中后四条为不可突破的红线：

- 多源风险画像
- 抽样资源编排
- 主体关联识别
- 布控效果复盘
- 低价本身绝不能直接成为违法结论
- 现场人员只接收执行所需线索
- 平台按正式请求提供商品信息
- 重排资源时保留原始计划

风险信号（`risk_signals`）记录布控汇入的数据来源：价格分布、历史抽检、投诉、认证、商家关联、渠道曝光。

重排触发（`replan_triggers`）记录允许重排资源的情形：主体改名、季节波动、计划撞车、样品失效、风险突然升级。

复盘指标（`review_metrics`）记录管理者回看原始计划时关注的维度：命中率、覆盖盲区、商家规避行为。

## 本地校验

仓库内的读取模块负责校验示例资料的领域标识、版本、参与方、事实、约束、风险信号、重排触发和复盘指标。运行项目自带测试即可检查这些基础资料能够稳定读取。仓库不保存账号、密钥、连接串或真实身份信息。
